# 第一版 · 开发路线图

> 项目：妙恋畅语 ｜ 文档版本：v1.0 ｜ 编写：阿砚 ｜ 2026-10-25
> 前提：Flutter 3.47.8 已装好；BYOK + 攻略面板两条硬约束已定；零基础，单人开发。

---

## 一、核心原则：竖着切一刀，不要横着一层层做

零基础最容易走错的路是"先把 Dart 学完，再学 Flutter，再做页面"。这条路通常走到三分之一就停了,因为它**长时间看不到东西**。

正确的切法：**从界面切到数据，打通一条最窄的完整链路，再把它加宽。**

```text
横切（不要）：把 10 个页面每个都做 10%  → 永远没有一个能用的
竖切（要）  ：1 个页面做到 100%，再接数据 → 第二个页面照着抄，快十倍
```

## 二、四步走

| 步 | 做什么 | 验收标准（做完能看到什么） | 需要 API？ | 需要 Android？ |
| --- | --- | --- | --- | --- |
| **1** | 用假数据把「攻略面板」第一屏画出来 | Edge 里看到妙恋畅语的面板，不是计数器 | 否 | **否** |
| **2** | 面板数据从写死改成「一个 model 文件里读」 | 点首页对象卡能进面板，数据来自同一份 model | 否 | 否 |
| **3** | 粘贴聊天 → 调 DeepSeek → 结果进面板 | 真粘贴一段对话，真生成一条回复 | **是** | 建议真机 |
| **4** | 补齐其余页面 + 本地存储 | 关掉 App 再打开，对象和记录还在 | 是 | 建议真机 |

**时间感（零基础，每天 2 小时）：** 第 1 步 3～5 天，第 2 步 3～4 天，第 3 步 5～7 天（要查网络请求和错误处理），第 4 步 1～2 周。

**这个排期比项目书里的 8 周宽，是因为原计划假设你会写代码。** 事实是你在同时学语言和写产品，两个都要时间。宁可把日历拉长，也不要把每步做成半成品。

## 三、第一步：具体动作

```bat
cd /d E:\妙恋畅语
flutter create --platforms=windows,web app
cd app
flutter run -d edge
```

三件事要理解，不是照抄：

1. `flutter create` 建的 `app` 目录是**代码区**，和 `first/`（文档区）分开。文档归文档，代码归代码。
2. `--platforms=windows,web` 先不建 android/ios，**因为阶段 1 还没装**。以后要加，一条命令就行。
3. `flutter run -d edge` 第一次会慢（要编译），**不是卡死**。

跑起来之后，立刻做一件事：**把 `lib/main.dart` 里那个计数器删干净，换成一句话。**

> 「今天，想和谁聊聊？」

就一行字。**这一行的意义是：从这一刻起，这个项目不再是一个教程练习。** 屏幕上出现的是你的东西。

## 四、两条纪律

### 纪律一：边做边学，不要先学语言

遇到不懂的关键字就查，查完就用。等你能画出一个卡片，你会发现自己已经会了 `Widget`、`build`、`Column`、`Padding`、`TextStyle`——这些占实际开发 80%。

**反例**：花两周看完 Dart 官方教程，然后发现自己还是不知道怎么写一个圆角卡片。因为教程教你语法，不教你怎么把设计稿变成界面。

### 纪律二：代码用 git，不用 versions 目录

`first/versions/` 那套是给**文档**用的，代码有更趁手的工具：

```bat
cd /d E:\妙恋畅语\app
git init
git add .
git commit -m "初始工程"
```

之后每次能跑通了就 commit 一次。代码改动频繁、颗粒度小，用目录复制会瞬间失控；git 天生干这个（本机 git 2.55.0 已装）。

**两套并行，不冲突**：文档看 `first/CHANGELOG.md`，代码看 `git log`。

## 五、明确不做什么（这一节比上面都重要）

| 不要做 | 为什么 |
| --- | --- |
| 先系统学完 Dart 再看 Flutter | 会停在第三分之一 |
| 一开始就搭 10 个页面 | 每个都是半成品，等于没有产品 |
| 先上后端 / 数据库 / pgvector | **见下节，BYOK 之后这些可以整体推迟** |
| 第一步就接 API | 你还没界面，接了也没地方显示结果 |
| 追求好看的动效 | 先让它能跑，动效是最后 10% 的事，且最花时间 |

## 六、一个建议调整（待你确认，我不擅自改项目书）

项目书 §9 写的是：**FastAPI + PostgreSQL + pgvector**。

但约束一（BYOK）定下来之后，这三件套的必要性下降了：

- **FastAPI**：客户端直接调 DeepSeek，中间不需要转发服务器。
- **PostgreSQL**：单人本地使用，`sqlite` 或直接一个 json 文件就够。
- **pgvector**：模板库只有一两百条，用关键词 + 简单相似度就够，不需要向量数据库。

**换句话说：约束一顺手把整个后端复杂度清掉了。** MVP 可以是一个**纯客户端 App**，装在自己手机上、用自己填的 Key、数据存在本机。

这不是"降级"，是**把最难的三件事（部署、鉴权、数据库运维）推迟到你真的有多用户需求的那天**。

**代价**：换手机数据会丢（要配套导出/导入）；多个设备不能同步。

要改我就改 §9，不改就按原方案留着。**这一步等你点头。**
