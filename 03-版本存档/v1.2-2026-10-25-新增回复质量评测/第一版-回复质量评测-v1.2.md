# 第一版 · 回复质量评测

> 项目：妙恋畅语 ｜ 文档版本：v1.2 ｜ 编写：阿砚 ｜ 2026-10-25
> 目的：验证一件事——**生成的三条回复，用户敢不敢直接发出去。**
> 这一步不写代码、不用 API、不花钱。它决定的是"要不要继续做"，不是"怎么做"。

---

## 1. 为什么先测这个

整个产品成不成立，只看一个假设：**回复可用**。

如果三条里一条都不敢发，那后面的模板库、关系阶段、隐私页、8 周排期全部建立在沙子上。这个测试花你一个下午，可能省下六周。

## 2. 通过线（先定死，不许事后放宽）

| 指标 | 通过线 | 说明 |
| --- | --- | --- |
| 总体可用率 | **≥ 60%** | 评委选"会直接发"或"小改后发"的占比 |
| 越界次数 | **0 次** | C 组（边界场景）里出现推进邀约的回复，一次就否决 |
| 压迫感投诉 | **≤ 1 次** | 理由里出现"油""压迫""不尊重""像推销"等，超过一次算味道问题 |

三条是全方位的：**总体过 60% 但越界一次，判定失败。** 因为这个产品的失败不是"不好用"，是"用错地方"。

## 3. 评分卡（发给评委的就是这一张）

每条回复只打三档，凭第一感觉，不要反复琢磨：

| 档 | 含义 |
| --- | --- |
| **① 会直接发** | 复制过去就能发，不用改 |
| **② 小改后发** | 换几个词就发，骨架是对的 |
| **③ 不会发** | 发出去会尴尬 / 会掉价 / 会让人不舒服 |

选 ③ 的，在"哪里不对"里挑一个（可多选）：

`太油` `太生硬` `太急` `不像人话` `有压迫感` `太卑微` `答错重点` `其他：____`

每组最后还有一个开放题（一句话就够）：
**"这组里你本来会怎么回？"**

## 4. 样本（10 组，每组 3 条候选回复）

> 评委须知：每组只有对话和三条回复，**没有评分标准、没有 AI 的推理过程**。这是故意的——你只需要判断"能不能发"。

## 5. 怎么用（你自己看，别给评委）

1. **只发第 3 部分和第 4 部分。** 第 1、2、5、6 部分会泄题。
2. **每人一份，独立评分，不许讨论。** 讨论会互相影响，样本就白了。
3. **别告诉评委"这是我们做的产品"。** 说"帮我看几条聊天回复写得怎么样"就够，避免他们客气。
4. 找 3 人起，5 人更好。人太少，一个人的口味就能拉偏结果。

## 6. 算分

```text
每条回复一人一档，共 10 组 × 3 条 = 30 条 / 人
可用 = ① + ②
可用率 = 可用条数 / 30

三人可用率取平均；任一人低于 50% 要单独看理由
```

判定：

| 结果 | 动作 |
| --- | --- |
| 可用率 ≥ 70%，越界 0 | 假设成立。进第 2 周：建 100 条种子模板，把"好回复"固化下来 |
| 60% ~ 70% | 能用但不稳。**不要指望模型直出**，模板库是必需品，扩到 200 条 |
| < 60% | 核心假设不成立。别做 App，先缩到"只帮接话、不做邀约"，重新测 |
| 越界 ≥ 1 次 | 无论可用率多少都判失败。边界逻辑必须先做成硬过滤，再谈别的 |

## 7. 答案键（设计者侧，评委绝对不能看到）

| 组 | 陷阱在哪 | 预期 |
| --- | --- | --- |
| A1-1 | 第一次聊天就评价外貌（"不像来还礼像来抢镜"） | 越界风险：太快、太油 |
| A2-3 | 对方冷淡时自己先撤 | 太卑微，等于替对方判断"不想聊" |
| A3-3 | 空泛夸赞，没接住"怀疑人生"这句情绪 | 答错重点 |
| B1-1 | "申请加入"是索取式玩笑，关系没到这一步会显得油 | 看评委对"油"的容忍度 |
| B2-3 | "别想太多"是最典型的无效安慰 | 应该被大量打 ③ |
| B3-3 | "你想干什么我都可以"把自己放到陪衬位 | 太卑微，且把决定责任推给对方 |
| **C1-1** | 道歉式开场，把"对方没回"变成"我错了" | 姿态过低，但**不算越界** |
| **C2-3** | **无视"改天吧"，直接定下周六** | **这是本测试最重要的一条。被打 ① 就等于产品会教人越界** |
| **C3-3** | 追问"我哪里不合适"，把拒绝变成谈判 | 有压迫感 |
| D1-2 | "是不是我说错话了"是自我中心的猜测 | 把气氛变得更沉 |
| D1-3 / C1-2 | "不发"作为候选，测用户能否接受产品劝退 | 如果评委普遍给 ①，说明"不发"是被需要的功能 |

**如果 C2-3 被任何一位评委打 ①**，说明普通人对"对方说改天吧"的敏感度比我们想的低——这不是评委错，这是产品必须替用户把关的理由。**这条数据本身就是 P0-2 的答案。**

## 8. 一个诚实的提醒

这 30 条回复是我写的，不是真模型跑出来的。所以这个测试测的是**"这类回复的写法能不能用"**，不是**"某个模型能不能稳定写出这类回复"**。

两者都重要，但顺序是这样：先证明"这么写有用"，再去解决"怎么让它稳定写出来"。**如果连最好的写法都不能过 60%，那换成什么模型都没用。**
