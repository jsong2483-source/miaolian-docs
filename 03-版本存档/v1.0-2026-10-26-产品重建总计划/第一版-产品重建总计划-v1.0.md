## 2. 产品定位与核心使用闭环

妙恋畅语应帮助用户完成以下完整流程，而不只是展示关系温度曲线或生成话术：

1. 管理聊天对象：创建人物、编辑资料、切换对象。
2. 导入聊天记录：添加截图或粘贴文本，并确认说话人。
3. 分析关系与互动：查看四维趋势、分析阶段、证据和边界提示。
4. 获取回复建议：查看候选回复、修改内容、复制使用。
5. 保存并持续跟踪：查看历史分析、温度曲线，并在登录后的设备之间同步。

### 产品底线

- 数据保存状态必须真实；不能把仅保存在内存中的数据显示为已持久化。
- 关键操作必须有明确的成功、失败、加载、重试或同步状态。
- 分析结论应保留证据引用、缺失值处理和边界优先规则，不能为了填满界面而编造分数。
- 视觉与功能均需验收，不能仅以页面能打开作为交付标准。

### 模块需求

#### 3.1 账号与登录
- 手机号验证码登录。
- 微信授权登录。
- 同一用户绑定两种登录方式后，应进入同一账号，避免产生两份人物数据。
- 支持退出登录、重新登录、账号注销与数据删除申请。
- 登录失效时，不得错误展示另一份空白或其他账号的数据。
- 当前已确认必须登录才能使用全部功能。

#### 3.2 人物与历史记录
- 创建人物，编辑昵称、关系背景等资料。
- 编辑、删除和切换人物。
- 每个人物拥有独立分析历史。
- 查看历史分析详情，包括四维数据、证据、阶段和回复建议。
- 数据修改后，相关页面保持一致。
- 删除人物时，明确说明关联记录的处理方式。

#### 3.3 聊天导入与分析
- 从分析页面直接开始新分析。
- 支持多张截图、粘贴文本和移除错误图片。
- OCR 后逐条确认说话人，并允许纠正识别错误。
- 分析前说明将发送哪些内容、发送给哪个服务。
- 分析过程中显示真实加载状态。
- 对断网、Key 错误、超时、服务端错误和不合法模型输出提供可理解的提示与重试。
- 成功分析后形成可追溯的分析记录。

#### 3.4 模板与回复
- 模板按初识、暧昧、冲突、边界等场景分类。
- 每条模板包含适用情景、内容和必要的使用提醒。
- 支持搜索、复制、编辑后使用。
- 回复建议可手动修改；修改后的文本不应意外覆盖原始分析结果。
- 从分析结果进入模板时，尽可能带入当前场景。

#### 3.5 我的与设置
- 展示登录账号、绑定方式和退出入口。
- 展示云端同步状态、最近同步时间及失败原因。
- API Key 的保存、验证、修改、清除均有明确结果。
- 区分网络错误、存储错误与 Key 验证错误。
- 提供隐私说明、数据导出与删除相关入口。

## 4. 技术架构建议

### 4.1 现有工程与新增能力的边界

现有交接材料提到 Flutter 前端、`AppState` 全局状态、人物仓库接口、SQLite、DeepSeek 模型层及统一数据模型。现有页面通过全局状态访问人物和分析数据。

新增规划能力包括：
- 身份认证服务；
- 云端 API；
- 云端数据库；
- 数据同步机制；
- 服务端访问控制；
- 必要的同步元数据与审计机制。

当前提供的工程材料并不能证明这些后端能力已经存在。

### 4.2 建议的分层

```text
Flutter 客户端
    ↓
AppState / 业务状态
    ↓
Repository 接口
    ↓
云端 API 客户端
    ↓
后端 API 服务
    ├── 身份认证与权限
    ├── 云端关系数据库
    ├── AI 分析请求（使用用户设备上的 Key 发起请求）
    └── 同步状态与必要审计信息
```

原始截图默认在本机处理，不主动上传。若分析需要调用 DeepSeek，识别后的聊天文本会发送给模型服务；产品必须准确说明这一点。

### 4.3 仓库接口与异步迁移

现有交接材料指出仓库接口为同步接口，多个页面依赖全局状态。云端请求具有异步性，因此不能简单地替换实现而不评估影响。

审计时需确认：
- 哪些仓库方法是同步的；
- 哪些页面直接依赖仓库或全局状态；
- 哪些操作需要改为异步；
- 是否需要阶段性兼容层；
- 加载、错误、重试和同步状态应由哪一层管理。

### 4.4 云端数据模型草案

| 实体 | 主要用途 |
|---|---|
| `users` | 内部用户 ID、账号状态、创建时间 |
| `auth_identities` | 用户 ID、手机号或微信身份标识、绑定时间 |
| `people` | 人物 ID、所属用户 ID、昵称、关系背景、创建与更新时间 |
| `analysis_records` | 记录 ID、人物 ID、输入类型、分析结果、创建时间 |
| `chat_messages` | 记录 ID、消息顺序、说话人、文本及必要来源信息 |
| `analysis_evidence` | 记录 ID、维度、等级、原文证据及来源引用 |
| `reply_suggestions` | 记录 ID、候选文本、类型、是否修改 |
| `templates` | 模板 ID、分类、正文、使用说明、版本 |
| `template_favorites` | 用户 ID、模板 ID、收藏时间 |
| `sync_metadata` | 用户/设备标识、同步游标、最近同步时间 |

以上是逻辑模型草案，不代表数据库表已创建。实施前需映射现有 `Person`、`Dims`、`TrendPoint`、`Reply`、`Tpl` 等模型，确认字段、标识与历史数据迁移方案。

## 5. 后端选型：托管、自建与混合方案

### 5.1 方案比较

| 维度 | 托管后端 | 完全自建后端 | 混合架构 |
|---|---|---|---|
| 初期开发 | 通常较快 | 较慢 | 中等 |
| 运维负担 | 较低，但仍需监控与备份核查 | 最高 | 中等 |
| 业务控制力 | 受服务商能力与接口影响 | 高 | 较高 |
| 微信登录 | 需核实自定义 OAuth/服务端适配能力 | 仍需自行实现并对接微信 | 可由自建适配层处理 |
| 手机号登录 | 依赖服务商、地区和短信供应商配置 | 需自行接入短信服务并实现安全控制 | 可自行控制认证适配 |
| 数据库管理 | 服务商提供托管能力 | 自行维护数据库、备份和恢复 | 数据库托管，部分业务自建 |
| 主要风险 | 服务商依赖、地区可用性、计费与迁移 | 安全维护、运维、备份恢复责任较重 | 系统边界更复杂 |

### 5.2 候选方向

**Supabase Cloud**
- PostgreSQL 关系型数据库适合人物、分析记录、证据、回复等有关联的数据。
- 需核实手机号 OTP、短信供应商、微信自定义 OAuth 接入、数据区域和当前计费规则。
- 需正确配置数据库行级安全策略（RLS）及服务端权限。

**Firebase**
- Firestore 适合文档式数据与相关 Firebase 生态。
- 需核实目标地区手机号认证支持、短信配置、微信登录适配、计费与数据区域。
- 必须正确配置 Firebase Security Rules 与服务端权限。

**初步建议：** 优先比较托管后端和混合架构，暂不锁定供应商。先验证目标地区的服务可用性、微信授权链路、短信送达、数据区域、备份能力和总成本。此处不进行实际部署或购买。

### 5.3 成本估算原则

需要分别核算：
- 后端、数据库和存储；
- 短信验证码；
- 域名、监控、备份与日志；
- 微信开放平台相关配置或服务；
- 网络和数据传输；
- 开发者维护时间；
- 用户自带 DeepSeek Key 所产生的模型费用（通常由用户自己的账户承担，仍需核实实际调用方式）。

任何供应商价格都应在选型时查阅官方最新价格页面；当前不把历史价格当成最终报价。

## 6. 账号与数据安全决策

### 6.1 账号与身份
- 手机号仅用于必要的身份验证和账号管理，不作为数据库主键。
- 使用内部用户 ID 作为数据归属根节点。
- 对验证码设置有效期、错误次数和发送频率限制。
- 微信授权必须由可信服务端验证，不能只信任客户端传来的身份标识。
- 账号绑定前确认身份归属；已有两个账号时不得直接覆盖，应设计安全的合并流程。
- 会话令牌存入系统安全存储，并支持过期、撤销和退出。
- 服务端每次读写都检查当前用户权限。

### 6.2 聊天数据
- 所有业务请求使用 HTTPS。
- 云端只保存实现功能所需的数据，并限制数据库和备份访问权限。
- 原始截图默认留在本机；未来若需上传，必须明确授权、用途、保留时间和删除机制。
- 日志不记录 API Key、验证码、访问令牌或完整聊天内容。
- 用户删除人物、分析记录或账号时，按公开的规则处理关联数据和备份。

### 6.3 用户自带 DeepSeek Key
已确认：**Key 只保存在本机，不做云端同步。**

| 项目 | 规则 |
|---|---|
| 保存位置 | Android 系统安全存储；平台支持情况需审计 |
| 云端数据库 | 不保存 Key |
| 源代码与日志 | 不写入代码、普通配置文件、版本存档或日志 |
| 同设备重启 | 应能重新读取并继续使用 |
| 换设备 | 用户在新设备上重新填写 |
| 清除 | 清除后停止后续使用，并明确反馈 |
| 验证失败 | 提示错误，不把无效 Key 标记为可用 |

系统安全存储能降低泄露风险，但不能保证在所有受攻击设备上绝对安全。用户自带 Key 也意味着分析文本会发送给 DeepSeek 服务；不得宣传为完全离线分析。

### 6.4 隐私与合规待核实项
若面向中国大陆正式发布，应核查：
- 云服务与数据库的数据存储区域；
- 适用的个人信息处理、告知与授权要求；
- 相关备案或许可要求；
- 微信开放平台接入条件；
- 数据删除与备份保留周期。

具体适用要求需要结合最终部署区域和业务形态确认，不在未核实前作确定法律结论。

## 9. 工程管理与版本纪律

1. 每批改动前记录需求编号、影响文件与验收标准。
2. 每批改动后执行 `dart analyze`、相关单元测试和集成测试。
3. 视觉改动单独记录，提供改前与改后截图。
4. 按项目既有规则存档到 `03-版本存档/vX.Y-日期-主题/`，并更新 `CHANGELOG.md`。
5. 真实 API 测试前确认额度与费用。
6. 数据库结构变化必须有迁移脚本、回滚方案和完整性检查。
